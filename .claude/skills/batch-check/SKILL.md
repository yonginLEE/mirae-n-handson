# 배치 점검

로그 폴더는 `$ARGUMENTS`로 받고, 인자가 없으면 `pipeline-samples/batch-logs`를 쓴다.
적재 건수 CSV는 로그 폴더의 상위 폴더에 있는 `datamart-counts.csv`다.

## 점검 기준

1. **실행 여부**: 다른 날에는 매일 도는 job이 그날 로그에 없거나, START만 있고 SUCCESS가 없으면 이상.
2. **중복 실행**: 같은 날 같은 job의 SUCCESS가 2건 이상이면 이상.
3. **적재 건수**: 직전 7일 평균에서 30%를 넘게 벗어나면 이상. 0건은 무조건 이상.
4. **지연**: 소요 시간이 그 job의 평소(중앙값)의 2배를 넘으면 이상.

## 규칙

- **근거 표기**: 이상마다 근거를 붙인다. 로그는 `파일:줄번호`, 건수는 CSV의 해당 줄 번호.
- **추측 금지**: 로그에 없는 원인은 추측하지 않는다. 원인은 "확인 필요"로 남기고, 무엇을 더 봐야 하는지만 적는다.
  로그에 적힌 사실(WARN 메시지, 운영자 조치 등)은 인용하되, 인과는 단정하지 않는다.
- **계산은 명령으로**: 평균·중앙값·편차는 암산하지 말고 awk나 스크립트로 계산한다.
- **로그 전체 읽기 금지**: 통째로 읽지 말고 grep · awk · wc로 필요한 줄만 뽑는다.
  먼저 한 파일의 앞부분만 보고 형식(START/SUCCESS, `date=`, `run_id=`, `elapsed=`)을 파악한다.
- 로그 파일명 날짜와 `date=`(대상 일자)가 같은지 확인하고, 표에는 대상 일자를 쓴다.
- 기준 밖이지만 눈에 띄는 것(반복 WARN 등)은 리포트 맨 아래 "참고"에 짧게 적는다.

## 리포트

점검을 마치면 먼저 표를 채팅에 보여 준다. 이상이 있을 때만 `docs/batch-check/report.md`에 저장한다.

1. 맨 위에 요약 한 줄: 점검 기간, 이상 건수(job·일 기준과 표 행 수 둘 다).
2. 이상 목록 표. 열은 날짜 / job / 점검 항목 / 근거 / 영향 추정 / 다음 확인 사항.
   영향 추정에는 로그로 뒷받침되는 범위만 "가능성"으로 쓴다.
3. 맨 아래에 "이상 없음으로 판정한 날짜" 목록.

**이상이 한 건도 없으면 파일을 만들지 않고 "이상 없음" 한 줄만 답한다.**
기존 `report.md`가 있으면 덮어쓰기 전에 사용자에게 알린다.
