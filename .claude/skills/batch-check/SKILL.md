# 배치 점검

로그 폴더는 `$ARGUMENTS` 로 받는다. 비어 있으면 `pipeline-samples/batch-logs` 를 쓴다.
적재 건수는 로그 폴더의 상위 폴더에 있는 `datamart-counts.csv` 를 쓴다.
파일명 날짜는 기준일이고, 실제 실행은 다음날 새벽이다.

## 점검 기준

1. **실행 여부**: 기준일마다 job 별 START 와 SUCCESS 가 각 1건씩 있어야 한다.
   SUCCESS 가 없거나, CSV 에 그 날짜·job 행이 없으면 이상이다.
2. **중복 실행**: 같은 날짜·job 에 START 나 SUCCESS 가 2건 이상이면 이상이다.
   `trigger=manual`, `lock=bypassed`, `--force` 기록이 있으면 근거에 함께 적는다.
3. **적재 건수**: row_count 가 직전 7일 평균 대비 ±30% 를 넘거나 0건이면 이상이다.
   7일치가 안 되는 초기 구간은 있는 날만으로 평균을 낸다.
4. **지연**: job 별 elapsed 중앙값의 2배를 넘으면 이상이다.

## 규칙

- **근거 표기**: 모든 이상에 `파일:줄번호` 와 해당 값을 적는다.
  예: `2026-09-15.log:40 elapsed=4357s`, `datamart-counts.csv:39 row_count=369064`
- **추측 금지**: 로그에 없는 원인은 추측하지 않는다. 원인 칸에는 "확인 필요"만 적고,
  무엇을 확인해야 하는지는 "다음 확인 사항" 칸에 쓴다.
- **계산은 명령으로**: 평균 · 중앙값 · 증감률은 awk, sort 같은 명령으로 계산한다.
  눈으로 세거나 암산한 값은 쓰지 않는다.
- 로그와 CSV 는 읽기만 한다. 수정하지 않는다.

## 리포트

저장 위치는 `docs/batch-check/report.md` 이다.

1. 제목, 점검 기간, 이상 건수 한 줄 요약 (날짜·job 기준 몇 곳인지 포함)
2. 점검 기준 요약과 데이터 출처
3. 이상 목록 표. 열은 아래 순서를 따른다.

   | 날짜 | job | 점검 항목 | 근거 | 영향 추정 | 다음 확인 사항 |

4. 참고 (계산 방식의 예외 등)
5. 이상 없음으로 판정한 날짜

**이상이 없으면 파일을 만들지 않는다.** 이상 없음이라고 채팅으로만 알린다.
이미 report.md 가 있으면 덮어쓰기 전에 사용자에게 확인한다.
