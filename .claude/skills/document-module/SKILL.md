# 레거시 모듈 문서화

대상: `$ARGUMENTS` 의 첫 인자(모듈 경로). 두 번째 인자가 있으면 그 범위만 본다.

**분석 대상 폴더의 파일은 읽기만 한다.** 수정 · 생성 · 삭제 · 실행하지 않는다. 쓰는 곳은 `docs/<모듈명>/` 뿐이다.

## 모듈명

`<모듈명>` 은 폴더 이름이 아니라 아래 셋 중 하나다. 표에 없는 경로면 멈추고 사용자에게 묻는다.

| 모듈 경로 | 모듈명 |
|---|---|
| `legacy/item-bank-php` | `item-bank` |
| `legacy/assignment-thymeleaf` | `assignment` |
| `legacy/grade-mssql` | `grade` |

## 절차

단계마다 결과를 파일로 저장한 뒤 다음 단계로 넘어간다. 저장하지 않은 채 다음 단계를 시작하지 않는다.

1. **계획 제시** — 읽을 파일 목록, 제외할 것(`vendor/`, 빌드 산출물 등), 범위, 산출물 3개를 먼저 보여 주고 확인을 받는다.
2. **진입점** — 요청을 받는 파일 · 컨트롤러 · 라우트를 찾아 `ARCHITECTURE.md` 에 저장한다.
3. **의존 관계** — 진입점에서 include · import · 호출을 따라가 누가 누구를 부르는지 적고 `ARCHITECTURE.md` 에 덧붙인다.
4. **데이터 흐름** — 스키마 · 뷰 · SQL 을 읽어 테이블, 관계, 읽기/쓰기 경로를 `ERD.md` 에 저장한다.
5. **비즈니스 규칙 후보** — 조건문 · SQL · 검증 코드에서 규칙을 뽑아 `BUSINESS-RULES.md` 에 저장한다.
6. **표본 점검 추천** — 사람이 직접 확인할 규칙 3개를 고르고 이유를 적는다. 반드시 "가장 그럴듯해 보이는(그래서 틀려도 안 들킬) 규칙" 1개를 넣는다.

## 규칙 형식

~~~markdown
### BR-01
- 규칙: (코드가 실제로 하는 동작 한 문장)
- 근거: `파일:줄번호`, `:줄번호`
- 근거 코드:
  ```언어
  (근거 줄을 그대로 인용)
  ```
- 확신도: 확실 | 추정
- 비고: (주석과 코드 불일치, 예외, 미확인 사항)
~~~

- 확실: 조건문 · SQL 로 확인함(실행은 안 했으면 그렇게 적음). 추정: 이름 · 주석으로 짐작함.
- 주석에만 근거가 있는 내용은 규칙으로 올리지 않고 별도 절에 모은다.

## 하지 말 것 (item-bank 검증 이력에서 실제로 틀린 유형)

- 뷰 · 스키마를 안 읽고 "확정 불가"로 남기지 않는다. 뷰 정의(`status = 'A'`)를 읽었으면 바로 판정됐다.
- 문자열 비교를 "정확히 일치"라고 쓰기 전에 테이블 콜레이션을 확인한다. `utf8mb4_unicode_ci` 라 대소문자를 구분하지 않았다.
- 일부 분기에서 본 동작을 "모든 경우"로 넓히지 않는다. id 오름차순 보조 정렬은 `id` 정렬에는 없었다.
- 한 분기에 있는 조건이 다른 분기에도 있다고 가정하지 않는다. `level < 5` 가 없는 분기가 있었다.
- 근거 줄번호는 조건이 있는 줄을 가리킨다. 옆 줄(`$types .= 'i'`)을 적은 적이 있다.
- 머리 주석 · 함수 이름만 보고 규칙을 쓰지 않는다. 주석으로는 난이도 5 제외를 알 수 없었다.
- 사소해 보이는 분기를 건너뛰지 않는다. 공백만 있는 키워드, 전체 건수의 `WHERE` 공유를 처음에 놓쳤다.
- 코드 · 스키마로 풀 수 있는 것을 "미확인"으로 남기지 않는다.
- 존재하지 않는 함수 · 파일을 적지 않고, 호출 방향을 거꾸로 적지 않는다. 쓰기 전에 grep 으로 확인한다.
