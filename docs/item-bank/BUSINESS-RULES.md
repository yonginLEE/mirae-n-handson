# item-bank-php 비즈니스 규칙 후보

> 대상: `legacy/item-bank-php` · 분석 범위: 검색 조건 조합 · 등록/수정 검증 · 목록 정렬과 제외 조건 · 분석일: 2026-09-29
> 선행 문서: [ARCHITECTURE.md](ARCHITECTURE.md), [ERD.md](ERD.md). `vendor/` 는 읽지 않았다.
> 근거는 `파일:줄번호` 이다. PHP 파일은 `legacy/item-bank-php/` 기준, 스키마 · 시드는 저장소 루트 기준(`db/mariadb/init/...`)이다.

읽는 법

- **확실**: 조건문 · SQL 로 동작을 확인했다. 단, 코드를 읽어서 확인한 것이고 실행해 보지는 않았다.
- **추정**: 이름이나 주석으로 짐작했다. 이번 목록에는 추정 규칙이 없다. 주석에만 근거가 있는 내용은 규칙으로 올리지 않고 6장에 모았다.
- 규칙은 코드 기준으로 적었다. 주석이 다르게 말하면 비고에 남겼다.

## 1. 문항 검색 — 조건 조합 (`search.php`)

### BR-01
- 규칙: 검색 조건(키워드 · 단원 · 난이도 · 태그)이 여러 개 들어오면 모두 AND 로 묶는다.
- 근거: `search.php:44`, `:98`, `:118`, `:215`, `:218`, `:226`, `:244`
- 근거 코드:
  ```php
  $where    = " WHERE 1=1";
  $where .= " AND unit_code = ?";
  $where .= " AND level = ?";
  ```
- 확신도: 확실
- 비고: OR 조합이나 조건 그룹은 없다.

### BR-02
- 규칙: 같은 파라미터가 배열로 여러 개 들어오면 첫 값 하나만 조건으로 쓴다.
- 근거: `search.php:51`, `:55`, `:59`, `:63`, `:67` (sort · dir · page 도 같다: `:71`, `:75`, `:79`)
- 근거 코드:
  ```php
  // 파라미터 꺼내기 (배열로 들어오면 첫 값만 쓴다)
  $tag = is_array($params['tag']) ? (string)reset($params['tag']) : (string)$params['tag'];
  ```
- 확신도: 확실
- 비고: 그래서 단원 · 난이도 · 태그는 한 번에 한 값만 걸 수 있다. 여러 태그를 동시에 거는 검색은 없다.

### BR-03
- 규칙: 키워드가 있으면 앞뒤 공백을 지우고, 제목 또는 지문에 키워드가 들어 있는 문항을 찾는다.
- 근거: `search.php:85`, `:97-98`
- 근거 코드:
  ```php
  $like = '%' . $q . '%';
  $where .= " AND (title LIKE ? OR stem LIKE ?)";
  ```
- 확신도: 확실
- 비고: 지문(`stem`)은 검색 대상이지만 결과 표에는 나오지 않는다 (`search.php:521`, `:672-679`). 대소문자 구분은 DB 콜레이션(`utf8mb4_unicode_ci`, `01-schema.sql:33`)을 따른다.

### BR-04
- 규칙: 키워드가 100자를 넘으면 100자로 잘라 검색하고 경고를 띄운다.
- 근거: `search.php:86-88`, `:494`
- 근거 코드:
  ```php
  if (mb_strlen($q, 'UTF-8') > 100) {
      $q = mb_substr($q, 0, 100, 'UTF-8');
  ```
- 확신도: 확실
- 비고: 매직 넘버 100. 입력칸의 `maxlength="100"` (`:494`)과 서버 검사가 같은 값을 따로 들고 있다.

### BR-05
- 규칙: 키워드가 한 글자이면 경고만 띄우고 그대로 검색한다.
- 근거: `search.php:91-92`
- 근거 코드:
  ```php
  if (mb_strlen($q, 'UTF-8') === 1) {
      $warnings[] = '키워드가 한 글자라 결과가 많을 수 있습니다.';
  ```
- 확신도: 확실
- 비고: 최소 길이 제한은 없다.

### BR-06
- 규칙: 키워드에 `%` 나 `_` 가 있으면 이스케이프하지 않고 LIKE 와일드카드로 쓰며, 경고를 띄운다.
- 근거: `search.php:94-95`, `:97`
- 근거 코드:
  ```php
  if (strpos($q, '%') !== false || strpos($q, '_') !== false) {
      $warnings[] = '키워드의 % 와 _ 는 와일드카드로 처리됩니다.';
  ```
- 확신도: 확실
- 비고: 경고 문구대로 동작한다. `%` 를 글자 그대로 찾는 방법은 없다.

### BR-40
- 규칙: 키워드가 앞뒤 공백을 지운 뒤 비어 있으면(공백만 입력) 키워드 조건을 붙이지 않는다.
- 근거: `search.php:85`, `:90`
- 근거 코드:
  ```php
  $q = trim($q);
  if ($q !== '') {
  ```
- 확신도: 확실
- 비고: 교차 검증(CROSS-CHECK CX-01)에서 추가. 한 글자 경고(BR-05) · 와일드카드 경고(BR-06)도 이 `if` 안에 있어 빈 키워드에는 뜨지 않는다 (`:91-96`).

### BR-07
- 규칙: 단원 코드가 있으면 앞뒤 공백을 지우고 단원 코드가 같은 문항만 찾는다.
- 근거: `search.php:109`, `:118-120`
- 근거 코드:
  ```php
  $where .= " AND unit_code = ?";
  ```
- 확신도: 확실
- 비고: 단원은 id 가 아니라 **코드**로 거른다 (등록 화면은 id 로 받는다, BR-19 참고). 비교는 대소문자를 구분하지 않는다 — `unit` 테이블이 `utf8mb4_unicode_ci` 로 선언돼 있다 (`01-schema.sql:18`). 9장 1번.

### BR-08
- 규칙: 단원 코드가 형식(영문 1자 + 숫자 1~2자리 + `-` + 숫자 1~2자리)에 맞지 않거나, 소문자가 섞였거나, `unit` 테이블에 없으면 경고만 띄우고 입력값 그대로 조회한다.
- 근거: `search.php:111-117`, `:125`, `:141-142`
- 근거 코드:
  ```php
  if (!preg_match('/^[A-Za-z][0-9]{1,2}-[0-9]{1,2}$/', $unit)) {
      // 형식이 달라도 그대로 조회한다 (결과는 대개 0건)
  ```
- 확신도: 확실
- 비고: 형식 정규식이 매직 값이다. `unit.code` 컬럼은 `VARCHAR(16)` (`01-schema.sql:13`)인데 정규식이 허용하는 최대 길이는 6자다. 소문자 경고 문구는 "입력값 그대로 조회합니다"라고 하고 실제로 입력값을 바꾸지 않지만, 비교 대상 컬럼(`unit.code`)의 콜레이션이 `utf8mb4_unicode_ci` 라서 (`01-schema.sql:18`) **소문자로 넣어도 대문자 코드와 똑같이 맞는다** (예: `m5-1` → `M5-1` 문항이 나옴). 단원 이름 조회(`:125`)도 같다. 코드 · 스키마로 확인했고 실행해 보지는 않았다 — 9장 1번.

### BR-09
- 규칙: 난이도가 비어 있으면 난이도 5 문항을 빼고(`level < 5`) 찾는다.
- 근거: `search.php:211-216`
- 근거 코드:
  ```php
  // 난이도 값이 비어 있으면 전체 난이도 검색 (1~5 모두 포함)
  if ($level == '') {
      $where .= " AND level < 5";
  ```
- 확신도: 확실
- 비고: **주석과 코드 불일치.** 주석은 "1~5 모두 포함"인데 코드는 5를 뺀다. 검색 폼의 빈 값 선택지 이름도 "전체"다 (`search.php:192`). 시드 주석은 이 조건을 전제로 건수를 맞춰 두었다 (`db/mariadb/init/02-seed.sql:34`). 매직 넘버 5. 난이도 조건이 없는 상태가 없으므로 **조건 없이 검색해도 난이도 5 는 나오지 않는다.** 난이도 5 문항을 보려면 난이도 5 를 직접 골라야 한다 (BR-10). 파일 머리 주석 `level : 난이도 (1~5, 빈값 허용)` (`search.php:8`)만 봐서도 5 가 빠진다는 것을 알 수 없다.

### BR-10
- 규칙: 난이도가 1~5 중 한 자리 숫자이면 그 난이도의 문항만 찾는다.
- 근거: `search.php:217-221`
- 근거 코드:
  ```php
  else if (preg_match('/^[1-5]$/', $level)) {
      $where .= " AND level = ?";
  ```
- 확신도: 확실
- 비고: 같은 정규식이 등록 검증에도 있다 (`register.php:70`, BR-20).

### BR-11
- 규칙: 난이도가 1~5 한 자리 숫자가 아니면 경고를 띄우고, 입력값을 정수로 바꾼 값과 같은 난이도를 찾는다.
- 근거: `search.php:223-229`
- 근거 코드:
  ```php
  // 1~5 밖의 값은 그대로 정수로 비교한다 (대개 0건)
  $warnings[] = '난이도는 1~5 사이여야 합니다.';
  $values[] = (int)$level;
  ```
- 확신도: 확실
- 비고: PHP 의 `(int)` 변환 규칙상 `"3.5"` · `"3abc"` 는 3 이 되어 경고와 함께 **난이도 3 결과가 나온다.** `"abc"` 는 0 이 되어 0건이다. 주석 "대개 0건"은 이 경우를 말하지 않는다. 이 분기에는 `level < 5` 가 붙지 않으므로 (`:223-229`) `"5abc"` 처럼 5 로 바뀌는 값은 경고와 함께 **난이도 5 문항을 보여 준다.** 실행해 보지는 않았다 (9장 2번).

### BR-12
- 규칙: 태그가 있으면 앞뒤 공백을 지우고, 이름이 정확히 같은 태그가 붙은 문항만 찾는다.
- 근거: `search.php:235`, `:244-247`
- 근거 코드:
  ```php
  $where .= " AND EXISTS (SELECT 1 FROM item_tag it JOIN tag t ON t.id = it.tag_id"
          . " WHERE it.item_id = v_item_public.id AND t.name = ?)";
  ```
- 확신도: 확실
- 비고: 태그는 id 가 아니라 **이름**으로 거른다 (등록 화면은 id 로 받는다, BR-21 참고). 한 번에 태그 하나만 (BR-02).

### BR-13
- 규칙: 태그 이름이 50자를 넘으면 50자로 잘라 검색하고 경고를 띄운다.
- 근거: `search.php:240-242`
- 근거 코드:
  ```php
  if (mb_strlen($tag, 'UTF-8') > 50) {
      $tag = mb_substr($tag, 0, 50, 'UTF-8');
  ```
- 확신도: 확실
- 비고: 매직 넘버 50. `tag.name VARCHAR(50)` (`01-schema.sql:37`)과 같은 값을 코드에 따로 적었다.

### BR-14
- 규칙: 태그 이름에 `%` · `_` 가 있거나 등록되지 않은 태그이면 경고만 띄우고 입력값 그대로(정확히 일치로) 조회한다.
- 근거: `search.php:237-238`, `:250-260`
- 근거 코드:
  ```php
  // 등록된 태그인지 확인 (없어도 조회는 그대로 한다 → 0건)
  if ($opt['value'] !== '' && $opt['value'] === $tag) {
  ```
- 확신도: 확실
- 비고: "등록된 태그인지"는 PHP 에서 `===` 로(대소문자 구분, `:253`) 보고, 실제 조회는 SQL `=` 로 한다 (`:245`). `tag` 테이블이 `utf8mb4_unicode_ci` 라서 (`01-schema.sql:40`) SQL 쪽은 대소문자를 구분하지 않는다. 그래서 등록된 태그를 대소문자만 바꿔 넣으면 **"등록되지 않은 태그입니다" 경고가 뜨는데도 결과는 나온다.** 코드 · 스키마로 확인했고 실행해 보지는 않았다 — 9장 1번.

## 2. 문항 등록 · 수정 — 검증 (`register.php`)

**수정 기능은 없다.** 모듈 안에 `UPDATE` 문이나 수정 화면이 없으므로 (ERD.md 3장, 6장 1번) 수정 시 검증 규칙은 뽑을 것이 없다. 아래는 모두 등록(POST) 규칙이다.

### BR-16

- 비고: 매직 넘버 5. 가운데 공백은 글자 수에 들어간다 (주석과 코드 일치). 폼 라벨에도 "5자 이상"이 따로 적혀 있다 (`:143`).

### BR-17
- 규칙: 제목이 200자를 넘으면 거부한다.

### BR-19

- 비고: 문자열 비교라서 `"03"` 처럼 앞에 0 이 붙으면 거부된다. 비어 있어도 같은 오류 "단원을 선택해야 합니다."로 거부된다 (`:66-67`). 검색은 단원을 코드로 받는다 (BR-07).

### BR-20
- 규칙: 난이도가 1~5 중 한 자리 숫자가 아니면 거부한다.

- 비고: 매직 값 1~5. DB 에는 CHECK 제약이 없어 (`01-schema.sql:25`) 이 검사가 유일한 범위 검사다. 같은 정규식이 검색에도 있다 (`search.php:217`). 폼 선택지도 1~5 를 따로 만든다 (`:163`).

### BR-21
